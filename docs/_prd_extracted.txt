# 基于本地知识库的知识问答助手 PRD 开发文档 v2
## 1. 项目概述
### 1.1 项目名称
基于本地知识库的知识问答助手（Personal Knowledge Assistant, PKA）
### 1.2 项目定位
面向个人学习与技术沉淀的本地化 RAG + Agent 知识库系统，支持课程笔记、课件、项目文档等资料的语义检索与智能问答，并具备技术更迭自动评估与版本管理能力。系统默认采用本地 Ollama 部署 Qwen2.5 模型，同时支持阿里云百炼 DashScope 与 DeepSeek API 作为可选云端模型源，兼顾隐私安全与推理能力扩展。
### 1.3 核心价值
知识沉淀：将零散的学习资料转化为可检索、可对话的结构化知识库。
技术进化：自动评估新旧技术内容的稳定性与性能，智能决策是否替换。
隐私优先，灵活扩展：默认本地运行，数据不出本地；可按需切换至云端 API 获取更强推理能力。

### 2.1 用户角色
### 2.2 核心使用场景
复习场景：输入"Python 装饰器怎么实现？"，系统从已上传的 Python 课程笔记中检索并回答。
对比场景：上传一篇关于"Python 新异步语法"的文章，系统自动对比库中旧内容，判断是否值得更新。
追溯场景：查看某条知识的更新日志，了解该技术点经历了哪些版本变更及变更理由。
模型切换场景：本地模型推理速度较慢时，临时切换至 DeepSeek 或阿里云 Qwen 获取更快响应；处理敏感资料时切换回本地 Ollama。
## 3. 功能需求
### 3.1 功能模块总览
### 3.2 功能详细说明
#### 3.2.1 知识库入库（Ingestion）
支持格式：.pdf、.md、.txt、.docx
处理流程：
用户上传文件 → 系统读取文本内容
文本清洗（去除乱码、多余空白）
语义分块（按段落/标题切分，每块约 500-800 token）
向量化（调用本地 Embedding 模型，如 BGE-m3）
存入 ChromaDB，附带元数据：source（来源文件名）、version（版本号，默认 v1.0）、topic（自动提取主题标签）、created_at（入库时间）
验收标准：上传 10 页 PDF 文档，入库成功率 100%，单文件处理时间 < 30 秒。
#### 3.2.2 智能问答（QA Agent）
输入：用户自然语言问题
处理流程：
问题向量化 → 在 ChromaDB 中检索 Top-K（默认 K=5）相关文档块
将检索结果 + 用户问题组装为 Prompt → 调用当前配置的模型生成回答
回答中标注引用来源（文件名 + 页码/段落）
模型来源：根据环境变量 MODEL_PROVIDER 决定使用 Ollama、DashScope 或 DeepSeek。
验收标准：针对已入库内容提问，回答准确率 > 85%，首字响应时间 < 5 秒（本地模型）/ < 3 秒（云端 API）。
#### 3.2.3 技术更迭与版本管理（核心亮点）
触发方式：用户上传新文档时勾选"启用技术更迭评估"。
评估流程：
提取新文档中的关键技术点（通过 LLM 自动抽取关键词/主题）。
针对每个技术点，在知识库中检索已有的旧内容。
将新旧内容对比输入评估 Prompt：
系统 Prompt：你是一位资深技术评审专家。请对比以下[旧技术描述]和[新技术描述]，从稳定性（是否经过生产验证、社区成熟度）和性能（效率、资源消耗）两个维度进行评估。
输出格式：
决策：REPLACE / KEEP_OLD
理由：（100 字以内）
稳定性评分：1-5
性能评分：1-5
执行动作：
REPLACE：删除旧版本的向量数据，写入新版本，版本号 +1，记录更迭日志。
KEEP_OLD：不修改知识库，仅记录日志说明拦截原因。
验收标准：评估决策与人工判断一致性 > 80%，每次更迭操作均有完整日志记录。
#### 3.2.4 模型切换
配置方式：通过环境变量 MODEL_PROVIDER 指定模型来源，可选值：ollama、dashscope、deepseek。
统一接口：所有 Agent 模块通过 LangChain 的 BaseChatModel 抽象接口调用模型，切换模型源无需修改业务逻辑。
降级策略：云端 API 不可用时自动降级至本地 Ollama；本地模型不可用时提示用户检查 Ollama 服务。
验收标准：切换模型源后，问答与评估功能均能正常运行，无需重启服务。
#### 3.2.5 日志系统
日志类型：
operation.log：记录文件上传、入库、删除、模型切换等操作。
update.log：记录技术更迭评估结果（决策、理由、评分）。
error.log：记录系统异常与错误堆栈。
日志格式：[时间戳] [级别] [模块] 消息内容
验收标准：所有关键操作均可追溯，日志文件按日期滚动存储。

### 4.3 模型切换设计说明
配置入口：通过 .env 文件或 Streamlit 侧边栏下拉框选择模型源。
环境变量示例：
MODEL_PROVIDER=ollama

# Ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5:7b

# 阿里云百炼 DashScope
DASHSCOPE_API_KEY=sk-xxx
DASHSCOPE_MODEL=qwen-plus

# DeepSeek
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_MODEL=deepseek-flash
实现原则：QA Agent 与 Update Agent 仅依赖 LangChain 的 BaseChatModel 接口，不直接绑定任何厂商 SDK。模型工厂根据 MODEL_PROVIDER 动态初始化对应客户端，实现业务逻辑与模型来源的解耦。

## 8. 验收标准
基础功能：能成功上传 PDF/MD 文件，入库后可通过自然语言问答检索到正确内容。
更迭功能：上传新旧两版同一主题的文档，系统能输出评估决策（REPLACE/KEEP_OLD）及理由，并正确执行或拦截。
模型切换：在 Ollama、DashScope、DeepSeek 之间切换后，问答与评估功能均正常运行。
日志完整：所有入库、问答、更迭、模型切换操作均有日志记录，可追溯。
本地优先：在断网环境下，使用 Ollama 本地模型时核心功能仍可正常使用。
代码规范：模块化结构清晰，核心函数有注释，README 包含安装、配置与运行说明。
