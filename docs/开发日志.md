  其余为空目录骨架：`src/pka/{agents,core,ui}`、`data/{chroma,uploads}`、`docs`、`examples`、`logs`、`tests`。
- 环境核查：
  - Python 3.11.3（`.venv`），此前仅 pip/setuptools。
  - Ollama v0.40.3 运行中（localhost:11434）。
  - 已有模型：`qwen2.5:7b`（4.36GB，PRD 默认）、`qwen3.5:9b`、`nomic-embed-text`（768 维）。

- Embedding 缺 `bge-m3` → 后台 `ollama pull bge-m3` 补齐（忠实 PRD，中文友好）；

**产出**：`requirements.txt`、`.env.example`、`.env`（默认 ollama + bge-m3）。
**进行中**：后台 pip 安装依赖 + 后台拉取 bge-m3。

**发现并修复的严重缺陷（阻塞级）**
- **症状**：真实数据目录里入库「装饰器笔记」与「异步旧方案」后执行更迭，
  `装饰器笔记` 的 4 个块被一起删掉，而库里残留了与主题无关的 `_e2e_sample.pdf`。
- **根因**：`_old_context_and_sources()` 只按「来源名不同」筛检索结果，凡进入 Top-K 的来源都被当作"旧内容"，
  REPLACE 时整批 `delete_by_source`——一次更迭会误删无关资料。

## 第 7 步 · 前端两处交互缺陷修复（2026-11-02）

**用户反馈**：① 输入问题后点发送、按回车都没反应；② 左下角堆了一堆「新会话（0 条）」。

**缺陷 1：`st.chat_input` 放在 `st.tabs` 里不触发提交**
- 根因：Streamlit 的 `chat_input` 只支持主区域，放进 `st.tabs` 后能渲染但提交事件不生效，
  所以 `if not question: return` 永远命中——点发送/回车都像没反应。
- 修复：`app.py` 的问答输入改为 `st.form` + `st.text_input` + `st.form_submit_button`（表单内回车即提交），
  按钮与回车两条路径都可用。
- 布局：提交后把问答写进 `session_state.messages` 并 `st.rerun()`，
  避免新回答被渲染到输入框下方（重跑后按「历史 → 输入框」正常顺序显示）。

**缺陷 2：每次页面加载都新建一个空会话**
- 根因：`_init_state()` 里 `if "session_id" not in session_state: create_session(...)`，
  而 Streamlit 每次浏览器重连/刷新都是新的 `session_state` → 每刷一次就往 SQLite 写一条空会话，
  侧栏 `list_sessions()` 全量列出 → 堆出十几条「新会话（0 条）」。
- 修复：**会话改为按需创建**——`session_id` 默认 `None`，只有真正提问时才 `create_session(问题前 20 字)`；
  侧栏 `selectbox` 改用 `index=None` + `placeholder="选择历史会话…"`，当前无会话时不再强选第一条。
- 清理：`HistoryStore.purge_empty_sessions()`（DELETE 无消息的会话），页面首次加载时执行一次；
  已手工清理真实库中遗留的 **6 条**空会话（清理前 sessions=6/messages=0）。

**测试**（新增 3 例，共 50 例）
- `test_purge_empty_sessions`：有消息的会话保留，2 条空会话被清掉。

- `test_submit_question_creates_session_and_messages`：填问题 + 点「发送」→ 落 1 个会话、2 条消息；
