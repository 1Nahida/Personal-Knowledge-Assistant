# Python 异步编程旧方案：回调与线程池

## 回调函数方案

在早期 Python 项目里，处理并发 I/O 的常见做法是回调函数：
注册一个回调，等 I/O 完成后由框架调用。嵌套多层后形成"回调地狱"，
异常传播困难，代码可读性差。

## 线程池方案

另一种做法是 `concurrent.futures.ThreadPoolExecutor`：
把阻塞 I/O 丢进线程池，主线程等待 Future 结果。

优点：
- 编程模型简单，与同步代码接近
- 生态成熟，从 Python 3.2 起标准库支持

缺点：
- 每个线程有独立栈，默认 8MB 虚拟内存，线程数上千时内存压力明显
- 线程切换需要内核态参与，上下文切换开销较大
- GIL 限制下，CPU 密集任务无法真正并行

## 结论

对于高并发 I/O 场景，回调与线程池都能用，但前者可维护性差，
后者在连接数上万时资源占用偏高。
